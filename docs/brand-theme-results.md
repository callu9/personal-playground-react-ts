# 브랜드 테마 실험 결과

2026-11-25 · Windows · Node 24.20.0 · Google Chrome 158.0.8127.37

[정적 CSS와 동적 CSS-in-JS의 빌드·개발 반영·런타임 비교](experiments/brand-style-build-runtime.md)

## 초기 구현 당시 시간 기록

아래 시간은 이번 세션에서 관측한 후보 작업 구간으로 코드 작성, 도구 응답 대기, 첫 검증을 포함합니다. 공통 대시보드를 먼저 작성했고, 이후 후보가 앞의 작업을 재사용했습니다. 각 후보의 독립 구현 시간이나 사람의 순작업 시간을 추정할 근거로 사용하기 어렵습니다. 첫 렌더와 전체 동작 통과 사이의 시간, 재작업과 대기의 세부 구간은 계측하지 못했습니다.

| 후보 | 관측된 경과 | 이 구간에서 한 작업 |
|---|---:|---|
| CSS Modules + React Context | 2분 55초 | 공통 대시보드, 브랜드 정책, CSS Modules 스타일과 최초 브라우저 시나리오 |
| styled-components | 51초 이내 | 기존 스타일을 런타임 테마로 옮기고 브라우저 시나리오 통과. 다음 후보로 넘어간 시점까지가 관측 상한 |
| Tailwind CSS | 1분 22초 | 공통 마크업에 적용할 유틸리티와 브랜드 변수 연결 작성 및 첫 브라우저 검증 |
| shadcn/ui | 28초 | 이미 받은 레지스트리 컴포넌트 3개를 공통 화면에 연결하고 첫 빌드·브라우저 검증. 앞서 병행한 레지스트리 설치 시간은 구간에서 제외 |

공통 초기 설정, 후보별 동작 확인 이후의 리뷰와 보정, 전체 검증은 위 표에 포함하지 않았습니다. 이번 순서에서는 shadcn이 Tailwind 구현을 그대로 활용했으므로 구간 차이에는 재사용 효과가 포함됩니다.

## 동일한 테마 변경의 속도와 복잡도

초기 구현 순서에 따른 재사용 효과를 보완하기 위해, 커밋 `bd79702`의 화면에 **브랜드별 상세 모달 테두리 토큰**을 추가하는 변경을 다시 측정했습니다. 후보마다 기존 회색 테두리를 확인한 뒤 임시 복사본에 준비된 패치를 적용했습니다. Vite 재시작과 Chrome 검증을 포함해 최초 Grove 적용 시점, Grove·Signal·Ember와 로그아웃까지 전체 검증한 시점을 따로 잽니다. 후보별 3회 측정의 중앙값과 범위입니다.

| 후보 | 패치 적용 중앙값 | 최초 적용 확인 | 전체 검증 | 후보별 수정 파일 / 지점 | 이 변경의 적용 경로 |
|---|---:|---:|---:|---:|---|
| CSS Modules + React Context | 4ms | 592ms (544–639) | 820ms (772–897) | 1 / 1 | 공통 CSS 변수 → 모듈의 모달 테두리 |
| styled-components | 4ms | 559ms (521–726) | 787ms (752–985) | 1 / 1 | Provider의 테마 값 → 모달 스타일 보간 |
| Tailwind CSS | 10ms | 518ms (492–713) | 781ms (753–1024) | 2 / 2 | 공통 CSS 변수 → Tailwind 색상 매핑 → 모달 클래스 |
| shadcn/ui | 10ms | 690ms (606–1085) | 933ms (836–1422) | 2 / 2, shadcn 전용 0 / 0 | 공유 Tailwind 매핑과 모달 클래스를 그대로 사용 |

공통 준비에는 브랜드별 색상 3개, 토큰 타입, CSS 변수 출력 등 **1개 파일의 5개 지점**이 쓰였고 후보별 시간과 변경량에서 제외했습니다. shadcn의 파일 2개는 단독 재현에 포함된 Tailwind 파일이며, 두 후보를 같이 유지하는 작업량은 **총 2개 공유 파일**입니다. 이 실험의 모달은 공통 React 컴포넌트이므로 shadcn 레지스트리 컴포넌트 수정 비용은 여기서 계측하지 않았습니다.

시간은 준비된 패치의 적용부터 시작합니다. 사람이 처음 설계하고 편집하는 시간은 초기 구현 기록을 참고하며, 초기 도입 속도의 우열은 보류합니다. 재실행 시간은 브라우저와 Vite에 영향을 받으므로 표의 수십 ms 차이에 일반적인 구현 속도 순위를 부여하지 않습니다. 원시 기록의 각 행에서 세 구간을 확인할 수 있습니다. [12회 측정 원본](experiments/evidence/brand-outline-benchmark.json)

```sh
node scripts/measure-theme-change.mjs
```

## 브라우저와 빌드

`npm run build` 후 `npm run measure`로 로컬 프로덕션 빌드를 열었습니다. 후보별 1280×900의 새 Chrome 컨텍스트에서 Grove와 Signal을 번갈아 선택했습니다. 워밍업 2회 이후 20회를 기록했습니다. JS·CSS 크기는 각 HTML의 프로덕션 매니페스트에서 따라갈 수 있는 초기 자산을 중복 제거한 뒤 gzip으로 합산했습니다.

| 후보 | JS gzip (바이트) | CSS gzip (바이트) | 계정 상태 반영 p50 / p95 | 글꼴·버튼 색상 적용 p50 / p95 |
|---|---:|---:|---:|---:|
| CSS Modules + React Context | 74,134 | 2,189 | 16.6 / 16.8 ms | 16.7 / 16.8 ms |
| styled-components | 86,258 | 238 | 16.6 / 16.8 ms | 16.7 / 16.8 ms |
| Tailwind CSS | 75,411 | 4,738 | 16.6 / 16.8 ms | 16.7 / 16.8 ms |
| shadcn/ui | 88,571 | 5,791 | 16.7 / 16.9 ms | 166.7 / 166.9 ms |

계정 상태는 다음 프레임 콜백에서 DOM의 브랜드 값으로 확인했습니다. 스타일은 제목 글꼴과 첫 행 버튼 배경색의 계산값이 새 브랜드 값에 도달할 때까지 프레임마다 확인했습니다. 이 측정에는 프레임 대기 시간이 포함되며 실제 화면 표시 시점은 계측하지 않았습니다. shadcn 버튼의 기본 `transition-all`은 브라우저에서 150ms로 확인됐습니다. 이 애니메이션이 버튼 색상 정착 시간에 반영됐습니다.

Chrome 자동 테스트 14개에서 네 구현의 초기 env, 계정 전환, 재로드, 로그아웃, 모달과 키보드 포커스, 390px 화면에서의 테이블 스크롤을 확인했습니다. 기존 `callu9ine` Chrome 프로필에서도 네 페이지를 열고 Signal 또는 Ember의 모달 글꼴 및 버튼 배경색을 확인했습니다. 고정 데이터와 데모 계정으로 검증했으며 운영 로그인과 운영 배포는 검증 범위 밖입니다.

## 기준별 선택과 트레이드오프

세 번째 브랜드 **Ember**는 공통 `brands.ts`의 브랜드 값과 데모 계정 매핑 두 곳으로 지원합니다. 네 후보의 Provider나 스타일 파일에서 브랜드별 코드를 추가할 필요가 없었습니다. 시맨틱 토큰의 종류 자체를 늘리면 영향을 받는 스타일을 각 후보에서 수정해야 합니다.

| 후보 | 작성·유지 비용 | 적합한 조건 |
|---|---|---|
| **CSS Modules + React Context** | 별도 스타일 런타임 없이 클래스 스코프와 변수 적용. 컴포넌트 CSS는 직접 작성 | 기존 DS로 작은 실험을 빠르게 시작하고 로드 크기를 줄일 때 |
| **styled-components** | Provider 객체를 스타일에서 직접 참조. 전환 과정에 런타임 JS와 스타일 주입이 포함됨 | 컴포넌트가 테마에 따라 동적 스타일을 자주 계산할 때 |
| **Tailwind CSS** | 변수 매핑과 빌드 시 클래스 탐지가 필요. 긴 유틸리티 조합과 reset 범위를 관리 | Tailwind에 익숙한 팀에서 기존 DS 토큰을 여러 화면에 적용할 때 |
| **shadcn/ui** | Button·Card·Badge의 레지스트리 코드를 재사용. 기본 스타일, 토큰, 전환 효과를 DS에 맞춰 조정 | 필요한 컴포넌트가 이미 레지스트리에 있어 재사용 효과가 클 때 |

| 선택 기준 | 이 실험의 선택 | 근거와 조건 |
|---|---|---|
| 초기 구현 속도 | 판정 보류 | shadcn 연결 구간은 28초였지만 공통 화면과 Tailwind 작업을 선행 재사용했습니다. 같은 출발점의 새 화면 구현 시간은 미측정입니다. |
| 기존 브랜드의 시맨틱 토큰 적용 | CSS Modules 또는 styled-components | 모달 토큰 변경이 각 후보에서 1파일·1지점이었습니다. styled-components의 테마 보간에는 런타임 스타일 의존성이 추가됩니다. |
| 신규 브랜드 추가 | 네 후보 동률 | 공통 브랜드 값과 계정 매핑 2지점만 필요했습니다. 기존 토큰 계약을 그대로 쓰는 경우입니다. |
| 등록 브랜드 색상·글꼴과 빠른 개발 피드백 | CSS Modules + React Context | 후보별 수정 1곳, 브라우저 규칙 추가 0건. 이 환경에서는 빌드의 안정적 우위를 확인하지 못했습니다. |
| 초기 자산 최소화 | CSS Modules + React Context | JS·CSS 합계 76,323바이트로 가장 작았습니다. 스타일 직접 작성 비용이 있습니다. |
| 즉시 색상 반영 | CSS Modules, styled-components, Tailwind | 버튼의 계산된 색상이 p95 16.8ms에 도달했습니다. shadcn에서는 현재 버튼의 기본 150ms 색상 전환이 유지됩니다. |
| 기존 Tailwind 화면에 컴포넌트 재사용 | shadcn/ui를 조건부 선택 | Button·Card·Badge를 재사용했고, 모달 토큰 변경은 Tailwind와 공유했습니다. 제공 컴포넌트의 기본 스타일과 토큰을 DS에 맞추는 추가 비용이 생깁니다. |

이 대시보드의 기본값은 **CSS Modules + React Context**입니다. 기존 DS를 적용하는 범위에서 가장 작은 초기 자산과 한 곳의 후보별 테두리 변경을 확인했습니다. 화면 구조와 UI 기능은 공통이고, 컴포넌트 기본 스타일에 따른 세부 픽셀 차이는 남아 있습니다.
