# 03. Jonbeo MSW와 입력 지연

**상태** · 측정 계획. 당시 커밋, 문제를 보고한 입력 시나리오와 trace, MSW 초기화 경로는 확보 전입니다.

## 동일 과제

당시 프로덕션 빌드 설정과 입력 동작을 확보합니다. 같은 응답 본문과 지연을 사용해 세 조건을 비교합니다. 첫 방문과 재방문을 나누고, 동일한 CPU·네트워크 조건과 입력을 반복합니다.

| 비교 조건 | 재현 준비 시간 | 전체 검증 시간 | 변경 복잡도 | 비교 목적 |
|---|---|---|---|---|
| MSW 미실행 + 로컬 API | 미측정 | 미측정 | 미측정 | 동일 동작의 기준선 |
| MSW 실행 + 같은 API로 통과 | 미측정 | 미측정 | 미측정 | 워커 시작 및 요청 가로채기 비용 |
| MSW 실행 + 동일한 응답의 핸들러 | 미측정 | 미측정 | 미측정 | 모의 핸들러 코드와 응답 경로의 추가 영향 |

## 측정과 판정

- **재현 준비 시간**은 당시 조건 확인부터 첫 trace까지 잽니다. **개선 구현 시간**은 후보별 수정 착수, 개선 동작 첫 확인, 전체 회귀 검증 완료를 따로 기록합니다. 환경 복구와 기록 수집 대기도 함께 남깁니다.
- **복잡도**는 개선안별 수정 파일, 초기화·렌더링 경로 변경 지점, 추가 의존성, fallback/실패 처리 지점으로 비교합니다.
- **성능**은 당시 FID 기록과 로컬 INP·입력 지연, 긴 작업, 초기화 시간을 기록합니다. 원인이 드러난 구간에서 MSW 시작 순서, 모의 핸들러 작업, React 렌더링 등을 한 번에 하나씩 바꾸고 개선 전후의 trace를 첨부합니다.
- **선택 기준**은 입력 지연 개선 폭과 재현성, 개발·테스트 동작 유지, 변경 위험입니다. 당시 환경이 일부만 재현되면 현재 로컬 개선 효과와 과거 장애에 대한 인과 판정을 구분합니다.

원인과 개선안의 채택 여부는 실제 근거를 얻은 뒤 기록합니다.
